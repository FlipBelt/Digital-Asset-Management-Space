# 飞比特 AI 成果助手

版本：0.2.0。一个插件包含登记器和孵化器两项技能，并支持显式生成远程 MCP 连接配置。先从真实工作机会形成方案，或直接把已有成果整理为简明成果卡；默认保留本地草稿。

| 场景 | 技能 | 示例 |
| --- | --- | --- |
| 已有成果整理、AI 形成过程回顾、登记 | flipbelt-ai-asset-registrar | 帮我整理当前项目的成果卡，先保存本地草稿。 |
| 反复返工、需求探索、方案与交接 | flipbelt-ai-workflow-incubator | 帮我梳理这项重复工作，给出可试方案。 |

在宿主技能菜单或对话提及中选择对应技能。两项技能职责独立；形成成果后仅在用户选择登记时交接。没有文件能力时交付可复制文本，没有连接器时继续本地模式。

需要组织保存时先读 [连接器配置](CONNECTORS.md)。团队 App 引用候选只包含 `.app.json` 与 manifest 的 apps 引用；远程 OAuth 候选包含 `.mcp.json` 和宿主 manifest 引用；本机兼容模式不带自动 MCP 配置，千问包另附 Windows stdio 连接器源码和手动启动器。以本包顶部说明及 `SOURCE-PROVENANCE.json` 的 `connection_profile` 为准。

远程候选入口为 `https://jtzhzt.flipbeltchina.com/mcp`，部署与宿主状态以独立验证回执为准。宿主通过 OAuth 逐人授权后，才可能发现获授权的业务工具；远程实现共有13种业务工具，不含本机的 start_connection、complete_connection、disconnect。代码、配置或 ZIP 已生成都不能证明线上服务可用。

团队市场的远程分发必须显式提供真实资产 App 标识。打包器接受 `asdk_app_...` 或浏览器中的 `plugin_asdk_app_...` 技术标识，按官方规则去除一次 `plugin_` 前缀，并在 `.app.json` 声明必需 App；该团队包不携带直接 MCP 配置。未提供 App 时可准备本地直连候选，但不能同步到团队市场，也不借用 Knowledge App。个人 Codex 与千问远程包继续使用 MCP URL，不包含团队 App 标识。App 引用不创建服务、不授予权限；成员仍须独立授权。千问还需核对企业连接器、OAuth DCR 和开放策略。

本机兼容模式的千问包中，运行说明位于 `connector/README.md`。该适配器仅支持 Windows，需主动安装 Python、uv 和锁定依赖；安装或启动不会替本人授权。远程候选包不附带该旧运行资源，避免把远程附件当成服务器文件路径。

正式模式只保存用户授权的必要摘要；身份、类型和权限以服务端为准。每次变更保留 request_id，网络结果未知先查询回执。草稿私有，最终登记由本人打开 confirmation_url 核对确切版本并确认；待审核与真实业务验收分别报告。

三种分发均来自同一项目源并带 `SOURCE-PROVENANCE.json`。安装成功、实际工具发现、本人授权和真实登记闭环分别验证；远程总计13种业务工具，本机旧版为16个工具，可见数量还受权限及安装版本影响。企业环境尚需人工导入和代表性任务验收。

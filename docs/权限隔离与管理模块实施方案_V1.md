# 权限隔离与管理模块实施方案 V1

## 1. 正式资产责任模型

每项正式资产只维护三个面向使用者的责任字段：

1. **归属组织**：单选。选择公司主体时，数据库中的 `owner_department_id` 为空；选择部门时保存真实部门 ID。
2. **负责人**：单选且必填。每项有效资产只能有一名有效负责人。
3. **使用人员**：多选且可为空。负责人天然拥有使用和维护权限，不需要重复选择。

新登记资产先作为草稿；由部门负责人或资产管理员确认三项责任后转为正式在用资产，并记录确认人、确认时间和审核状态。

## 2. 角色与数据范围

| 角色 | 默认数据范围 | 核心权限 |
| --- | --- | --- |
| 普通员工 | 自己负责、使用或创建的资产 | 查看；负责人可维护基础资料、关系和使用人员 |
| 部门负责人 | 所管部门及下级部门资产 | 确认归属、调整负责人、处理部门交接 |
| 资产管理员 | 公司全部资产 | 资产治理、资料接入、跨部门调整 |
| 系统管理员 | 公司全部数据 | 角色、规则、集成和系统配置 |
| 审计人员 | 公司全部资产，只读 | 查询和审计，不可修改 |

页面菜单只用于降低操作复杂度；真正的权限判断在后端执行。直接调用接口也必须经过服务器会话和数据范围校验。

## 3. 权限继承

资产是权限范围的主节点。下列关联对象通过 `asset_id` 继承资产权限：

- 平台企业账号和访问账号；
- 凭据引用（只保存保险库引用，不在此表明文展示秘密）；
- 服务实例及用量指标；
- 自研系统接管资料；
- 资产关系、资产地图、搜索和工作台统计。

因此，同一项资产不会因切换到“平台与账号”或“服务与用量”路由而绕过权限。

## 4. 钉钉服务端会话

1. 前端在钉钉桌面容器中调用 JSAPI 获取一次性授权码。
2. 服务端使用授权码向钉钉换取用户身份，并匹配已同步的组织人员。
3. 系统自动创建或关联内部用户，按部门主管身份配置角色范围。
4. 服务端签发 HttpOnly、Secure 会话 Cookie；前端不再把本地存储中的人员 ID 当作可信身份。
5. “十叶-冯硕硕”首次成功进入时自动获得系统管理员和资产管理员角色。

前端同时兼容统一 `dd` 容器和钉钉桌面端 `DingTalkPC` 容器；普通浏览器不加载业务页面。

## 5. 上线验证与回滚

- 自动检查：后端 lint、API 测试、Alembic 迁移一致性、Vue 类型检查和生产构建。
- 生产健康检查：数据库正常、API 服务正常、未登录业务接口返回 401。
- 上线前快照：`/opt/account-center/backups/20260807-pre-permission-session-final/`，包含数据库、后端和前端。
- 若需回滚，先恢复该目录中的应用文件，再从 `database.dump` 恢复数据库。

## 6. 后续迭代

V1 已完成身份、责任和数据可见范围闭环。下一阶段可以在此基础上增加：审批通知、资产交接任务、批量责任确认、到期提醒和部门负责人工作队列；这些能力不需要再次改变六类核心对象模型。

# 数字中心：关联关系与到期责任治理

日期：2026-10-12。状态：实现、本地回归、测试回退演练及正式发布完成；已认证页面只读回读通过，人工业务验收独立。沿用本线程的发布授权。

## 管理边界

- 手机号与邮箱仅在「平台与账号 → 手机号与邮箱」维护。资产库、导出和个人资产列表按类型及注册身份对象表共同排除，防止历史错分类重新混入；原 UUID 和账号引用保留。
- 公司账号、个人订阅、子账号明细和平台目录由「平台与账号」管理。跟进页只呈现需要处理的公司账号与订阅、实际业务资产；个人订阅、通讯资源、子账号明细及已归类的平台目录不独立出现。
- 订阅按已保存的管理账号归组；尚未关联账号时按实际平台归组并明确提示。不按名称猜测账号、平台或订阅的关联。订阅实际到期日优先读取服务实例资料。

## 关系逻辑

关系分为「归属与管理」「部署与挂载」「调用与使用」「其他关联」。可选择现有平台、公司、部门及符合关系语义的资产或企业账号。没有现有对象时显示真实空状态，不自动创建平台或关系。

部署与挂载从当前系统指向承载它的平台、账号或云资源。账号和服务器提供反向的「承载系统（被部署）」「被系统挂载」；调用与使用同样提供被调用、被使用入口。保存前显示完整句子，保存后两端读取同一条关系。归属直接同步现有公司与部门字段，企业账号管理关系复用资源的管理账号字段。

新的写入接口校验对象权限、兼容类型、资料版本、请求编号及内容摘要；逆向操作需要能维护实际发出声明的对象。已有生效责任配置阻止直接更换公司，以免绕过交接。旧关系和历史编号继续可读，不删除历史数据。

## 负责人和 ID

- 生效负责人统一来自责任配置，概览、责任页、跟进页使用同一事实。只有登记建议时显示姓名与「待确认」；已离职或无效责任人明确需要交接，不冒充生效负责人。
- 企业账号的原生 ID 在概览的「平台账号 ID」单处维护；登记页只填一次。核验页引用这个值，专属资料不再重复要求填写，历史编号区域只读保留。
- ID 修改须管理员权限、版本和幂等编号，重复平台 ID 拒绝；修改后重新进入待核验状态。核验操作不另行覆盖 ID。

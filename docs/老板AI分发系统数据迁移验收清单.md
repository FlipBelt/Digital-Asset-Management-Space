# 老板 AI 分发系统数据迁移验收清单

## 目的与边界

本清单用于将 `FlipBelt AI 使用分发系统` 的真实业务数据导入集团账号管理中台。

- 本次由业务方确认静态 HTML 是完整来源，故以其作为本次导入的权威快照，SHA-256：`FE1C694A2DC7D3DB5FCFD9948CEDC6A3D417A0B6C569DF67C1CD4ECF6A00EB65`。
- 静态快照共有 45 条业务记录：15 个服务资产、5 条人员授权、10 条流水、2 条报销、4 条付款方式、3 个钉钉应用、6 条月度快照。
- 如未来在旧页面继续维护数据，则以老板浏览器 `localStorage.flipbelt_v3_data` 为准；它可能比 HTML 中的默认数据更新。
- 不在聊天、代码仓库、导入文件以外的非受控位置保存真实凭据、卡号或安全码。导入器会删除付款方式中的卡号与安全码字段。

## 一、确认导入来源

本次可直接上传项目内的 `FlipBelt_AI分发系统_v4(1).html`，不需要额外导出 JSON。导入页会解析其中的 `DEFAULT_DATA`，并保存文件指纹。

如果后续需要导入浏览器内较新的数据，按以下步骤导出 JSON。

在仍保留旧系统数据的老板浏览器中打开旧 AI 分发页面，按 `F12` 打开开发者工具，在 Console 执行：

```js
copy(localStorage.getItem('flipbelt_v3_data'))
```

将剪贴板内容保存为 UTF-8 文件，例如 `flipbelt_v3_data_YYYYMMDD.json`。不要编辑内容、不要截图代替导出、不要把真实支付卡号或安全码补写进文件。

如果浏览器不允许 `copy`，在 Console 执行以下代码下载 JSON 文件：

```js
const data = localStorage.getItem('flipbelt_v3_data');
const link = document.createElement('a');
link.href = URL.createObjectURL(new Blob([data], { type: 'application/json' }));
link.download = 'flipbelt_v3_data.json';
link.click();
URL.revokeObjectURL(link.href);
```

导出后，保留原旧页面和原浏览器数据，不要清空 localStorage，直至最终验收完成。

## 二、本地预演

1. 在“资料接入工作台”上传 JSON，或直接粘贴 JSON。
2. 核对识别数量、源文件指纹和以下分类：服务资产、人员授权、流水、报销、付款方式、钉钉应用、预算快照。
3. 检查付款方式行不再包含卡号、安全码或 CVV。
4. 暂存后选择正确的公司主体与老板登记人，执行“创建老板隔离试点”。
5. 用老板身份验证：可在“我的使用”和资产列表看到导入的服务及钉钉应用。
6. 用普通员工身份验证：在未确认授权前，看不到该试点新增资产。

## 三、生产导入前置条件

以下条件必须同时满足，才可进入生产导入：

1. 已确认本次以项目内静态 HTML 为权威快照，或已取得较新的 `flipbelt_v3_data` JSON 并完成差异确认。
2. 已确认公司主体与老板在钉钉组织中的人员记录；不能用临时姓名代替。
3. 已完成新的生产应用文件、前端构建产物和数据库备份；备份目录必须包含可恢复的数据库转储。
4. 已在本地运行 `scripts\verify.ps1` 且通过。
5. 已明确本次导入只创建老板隔离试点；人员授权、费用、报销和付款方式不自动生效。

生产服务器上的备份、部署和数据库操作必须由有权限的运维人员按现有 Nginx/systemd 部署规范执行。不要运行本项目仅面向本地开发的 PostgreSQL 启动或初始化脚本来操作生产。

## 四、导入后的对账标准

- 每个源记录有源类别、源标识和暂存记录，可按批次追溯。
- 服务资产和钉钉应用由老板登记并由老板作为唯一责任人；资产所属部门为空，状态为待确认。
- 钉钉应用的 `APIID` 能对应到历史 API 服务时，系统建立 `calls` 关系。
- 人员授权必须是 `pending_review`，匹配到唯一服务实例和钉钉人员后才允许确认生效。
- 流水、报销、付款方式和月度快照仅保留为待核对历史；不得计入当前正式费用统计。
- 管理员或审计员可追溯实际操作人；老板是业务登记人，不替代实际审计行为人。

## 五、完成判定

完成试点的条件是：老板确认服务与钉钉应用完整、员工在确认前不可见、历史来源记录可追溯、无敏感付款字段落库。完成财务迁移需要另行确认费用、报销和付款方式的正式业务规则后再启用，不能用本次试点自动替代。
